# Support

## Installation and use

Start with the [installation guide](docs/INSTALLATION.md), the
[documentation index](docs/README.md) and the in-app **Help** handbook. Include
the application version, host architecture, Docker or native Linux edition,
target hardware profile and image format when asking for help.

Search existing GitHub issues before opening a new one. A support report should
contain exact steps and sanitised logs. Do not upload copyrighted disk, dms or
ROM images. Create a minimal generated image where possible.

English Amiga Board discussions are useful for hardware history and format
evidence, but a reproducible application defect should also be recorded in
GitHub so its status is not lost.

## Defects and feature requests

Use the repository issue templates. A defect is behaviour that differs from
the documented contract or rejects media proven valid by the supported target.
A feature request should identify the user workflow, target format and safety
boundary rather than prescribing a particular internal implementation.

## Security and conduct

Security reports follow [SECURITY.md](SECURITY.md). Conduct reports follow
[CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Neither should be filed as a public
support issue.
