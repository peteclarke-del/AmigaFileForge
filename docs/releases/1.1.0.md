# Amiga File Forge 1.1.0

Amiga File Forge 1.1.0 adds SuperCard Pro flux support, container export,
reading and writing real disks through a Greaseweazle or a floppy controller,
and buildable Windows, macOS and RPM editions.

## Physical media

- Added Greaseweazle **read**, capturing a disk in a connected drive into a new
  working image. Captures can be taken as decoded OFS or FFS sectors, or as
  HFE or SCP flux for a disk of unknown condition. A capture is only opened
  once Greaseweazle exits cleanly and leaves a usable image, and a failed read
  removes its partial file.
- Added a floppy-controller adapter for a host with a real drive, such as a
  Raspberry Pi, reading and writing `/dev/fd0` directly with no external tool.
  Supported geometries are the Amiga double-density and high-density 3.5-inch
  disks, the 40-cylinder 5.25-inch disk, and the CrossDOS-compatible PC 720 KiB
  and 1.44 MiB disks.
- A controller capture is checked against the exact size of the chosen
  geometry. A short read is discarded rather than presented as a complete
  image, because a disk the controller could not fully decode must not look
  like one it could.
- Writing through the controller is refused until it is explicitly confirmed,
  and the image must match both a known Amiga geometry and the drive.

The two adapters are not equivalent. A floppy controller returns decoded
sectors and fails on anything it cannot decode; Greaseweazle captures flux
whether or not a filesystem decoder accepts it. The
[physical floppy guide](../PHYSICAL-FLOPPY-GUIDE.md) explains which to choose.

## SCP flux captures and container export

- Added SuperCard Pro SCP support, decoded through the bundled HxCFloppyEmulator
  command-line converter. A capture opens read-only unless it re-encodes and
  decodes back to identical sectors.
- Added **File, Export as** and a matching **Export** control in every pane
  header, converting an open image's decoded sectors into another compatible
  container. Every OFS or FFS image exports as its canonical sector image, and
  the double-density and high-density 3.5-inch floppies also export as HFE or SCP.
- Every flux export is decoded again and compared byte for byte with the working
  sectors before the file is released.
- The export control stays visible but disabled when an image has no compatible
  target, and its tooltip gives the reason.

## Windows, macOS and RPM editions

- Added a portable desktop shell using the system webview: WebView2 on Windows
  and WKWebView on macOS. The same private, token-authenticated server and the
  same frontend sit behind it, so shared behaviour cannot differ between
  desktops. Linux keeps the GTK host for its native menus, file chooser, drag
  and drop and file associations, and falls back to the portable shell when the
  GTK stack is absent.
- Per-user state now follows each platform's convention: XDG directories on
  Linux, Application Support on macOS, and Roaming with Local on Windows.
- Added RPM packaging. The RPM is produced from the same installed tree as the
  Debian package, so both distributions install byte-identical application
  trees under `/opt/amiga-file-forge`.

Docker and the Debian and Ubuntu packages remain the tested, released editions.
The RPM, Windows and macOS editions build from this tree and are covered by the
test suite, but are not yet part of the release matrix. See the
[cross-platform guide](../CROSS-PLATFORM.md).

## Correctness

- Fixed catalogue addresses being read inconsistently. `1900`, `&1900` and
  `0x1900` now mean &1900 everywhere a person can type an address, including
  the file-import review, **New file**, the file properties dialog and the
  headless `--load` and `--exec` options. Previously an unprefixed value
  reached the disk engine as decimal, so `--load 1900` meant &76C.
- Fixed the installed FFS menu launcher test, which raised `NameError` on
  every FFS image because it referenced an undefined name. The test that
  covered it had replaced the function with a mock, so nothing executed it.
- Fixed saving an edited double-density SCP capture. Only the HFE save path repaired an
  omitted trailing sector, so an SCP save failed its own verification.
- Whole-image searches now report how many files could not be read instead of
  dropping them silently.

## Security

- Restricted every outbound request to `http` and `https` and to publicly
  routable addresses. Catalogue sources are editable through the API, so
  without this an editable source list could reach services only the host can
  see. Set `AMIGA_ALLOW_PRIVATE_SOURCES=1` to allow a local archive mirror on a
  trusted network.

## Internal

- Flux-container policy for HFE and SCP now lives in one module, so a fix for
  one container cannot miss the other.
- Amiganut's private API is reached through a single reviewed adapter, checked
  against the pinned release by its own test.
- Added a correctness lint gate to CI, covering undefined names, unused
  imports, broken f-strings and syntax errors.
- The Debian package no longer ships build-machine bytecode, which was compiled
  for one interpreter in a package supporting several.
- The platform contract moved from version 5 to version 7 for the new desktop
  hardware and capture endpoints.

## Linux packages

The release provides packages for Debian 13 and Ubuntu 24.04 on AMD64, ARM64
and ARMv7. Choose the file matching both the operating system and processor.
For example:

```bash
sudo apt install ./amiga-file-forge_1.1.0-1~deb13_amd64.deb
```

An RPM can be built from the source tree with `tools/build-rpm-package.sh`.
