# Amiga File Forge 1.0.0

Amiga File Forge 1.0.0 is the first stable release of the Amiga media image
workshop. The web and native Linux editions share the same filesystem,
validation, editing and workspace implementation.

## Highlights

- Open, create, edit and save OFS ADF and ADZ images, FFS and AmigaDOS floppy
  and hard-drive images, Hardfile HDA and GEO pairs, HDF collections, DMS archives,
  HFE images, ROMs and writable Kickstart ROMs.
- Move files and complete disk images between movable workbench panes with
  format-aware preflight checks, filename resolution and Amiga load and execute
  metadata preservation.
- Browse HDF slots, retain empty slots, manage access state, audit menus, detect
  duplicate games and generate supported HDF menus.
- Traverse and maintain FFS directories, import OFS and FFS software with
  loader analysis, and validate edited images for the selected hardware.
- Inspect and edit BASIC, script, binary, archive and ROM content with token
  help, refactoring, disassembly, hex editing, comparison, structured analysis
  and guarded cheat candidates.
- Recover owner-isolated browser workspaces, use undo and named checkpoints,
  monitor long operations and save timestamped packages with technical README
  files and relevant sidecar metadata.
- Run as a local Docker service or as a native GTK 4 Linux application with
  desktop file associations, native file selection and file-manager drag and
  drop.
- Open and create HFE floppy images through the bundled HxCFloppyEmulator
  command-line converter (`hxcfe`). Clean sector-based HFE v1 images can be
  edited and are decoded again for byte-exact verification before download.
  Advanced HFE v2/v3, bad-sector and protected track layouts remain available
  as read-only extraction sources.

## Linux packages

The release contains separately built packages for Debian 13 and Ubuntu 24.04
on AMD64, ARM64 and ARMv7. Choose the package whose filename matches both the
distribution and processor architecture. Install it with APT so GTK,
Libadwaita, WebKitGTK and PyGObject are resolved from the operating system.

```bash
sudo apt install ./amiga-file-forge_1.0.0-1~deb13_amd64.deb
```

Ubuntu packages contain `ubuntu24.04` in place of `deb13`. Raspberry Pi OS
users should normally choose the Debian package matching `arm64` or `armhf`.
Each package contains an architecture-native build of the pinned
HxCFloppyEmulator command-line converter (`hxcfe`), `libhxcfe.so`,
`libusbhxcfe.so` and the upstream licence. HFE media can therefore be created,
opened and saved without a separate HxC installation. See the
[HFE and HxCFE guide](../HFE-HXC-GUIDE.md) for supported revisions and the
guarded save process.

## Upgrade and data safety

Installing the package over an earlier native build preserves XDG workspace
state. Docker users should retain the `amiga-file-forge-work` volume while
rebuilding. Save important edited images before upgrading and retain original
media when testing conversions on physical hardware.

The native packages do not contain commercial Amiga software, locally supplied
firmware or the managed emulator binaries from the Docker image. Emulator paths
can be configured in the workbench when native tools are installed separately.

## Known boundaries

- Unknown machine-code menu programs use a database-oriented preview unless a
  supported interpreter or emulator capture is available.
- AmigaBASIC 1.2 and unusual token streams remain read-only when safe retokenisation
  cannot be guaranteed.
- DMS edits that would change timing or unknown control chunks are rejected.
- Hardware-dependent loaders and protected software still require testing on
  the intended machine or an accurately configured emulator.
