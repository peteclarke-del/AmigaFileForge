# Amiga File Forge 1.4.1

A fix for DiskMasher archives. Anyone who opens `.dms` files should upgrade:
in 1.4.0 and earlier, a real archive was reported as damaged and could not be
rebuilt as an ADF.

## DMS archives failed to decode

Every track in a DMS archive carries two checks. The data as stored has a
CRC-16, and the data after unpacking has a plain 16-bit sum of its bytes.
Amiga File Forge compared the unpacked data against a CRC-16, so any track
whose sum and CRC differ was reported as "unpacked with a bad checksum", and
the rebuild refused the disk.

The synthetic archives the test suite builds made the same mistake, which is
why the suite passed. A real archive showed it at once: on 1.4.0,
`SKID_ROW-Compact128.DMS` from the amigascne.org archive fails 53 of its 80
tracks. The other 27 pass only because a track of one repeated byte can have a
sum equal to its CRC.

In 1.4.1 all 80 tracks check, and the ADF is byte for byte the one xDMS 1.3.2
writes from the same file. The xDMS source settles the format: the unpacked
data is compared with `Calc_CheckSum`, a sum of bytes, and only the stored
data and the headers are checked with a CRC.

## What else the rebuild now gets right

Some archives carry text as well as tracks: a banner stored as track 0xFFFF, a
FILE_ID.DIZ stored as track 80, and sometimes a short advertising boot block
stored as a second track 0. xDMS writes only tracks longer than 2048 bytes to
the disk. Amiga File Forge now does the same, so the DIZ text no longer lands
on a cylinder of the rebuilt disk and an advertising boot block no longer
replaces the real one.

A high-density archive has 22 sectors a track. The rebuild used to assume 11,
and now takes the track size from the archive, so a 1.76 MB disk rebuilds at
its full size.

## Editing a DMS track

Replacing an uncompressed track at the same length wrote a CRC-16 into the
field xDMS reads as the sum, so an edited archive would have failed in xDMS
and on an Amiga. The rebuild now writes the sum there.

The DMS project table heads that column "Unpacked sum", and the Help and the
README say checksums rather than CRCs.

## Repair and format behaviour

No format restriction has changed. A DMS archive that 1.4.0 opened is read the
same way by 1.4.1, except that tracks it wrongly marked as damaged now decode.
Nothing about other image formats has changed.

## Linux packages

The release provides packages for Debian 13 and Ubuntu 24.04 on AMD64, ARM64
and ARMv7. Choose the file matching both the operating system and processor.
For example:

```bash
sudo apt install ./amiga-file-forge_1.4.1-1~deb13_amd64.deb
```

The packages include the native GTK launcher, desktop integration and the
bundled HxCFloppyEmulator runtime for HFE and SCP media, as they did in 1.4.0.
Installing 1.4.1 over 1.4.0 preserves native XDG workspace data and Docker
working volumes. Save important open images before upgrading.

See the [installation guide](../INSTALLATION.md) and
[Linux desktop guide](../LINUX-DESKTOP.md) for setup and troubleshooting.
