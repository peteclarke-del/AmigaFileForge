# Amiga File Forge 1.5.0

Check for Application Updates. The About box can now ask GitHub whether a newer
release exists, and a package installed from a release can install the update
and restart itself.

Nothing in this release changes how an image is read or written. Upgrade to
get the update check; later releases can then be installed from the About box.

## Check for Application Updates

**About Amiga File Forge**, in the **Help** menu, has a **Check for
Application Updates** button. Nothing is sent to GitHub until it is pressed.
It reads the repository's latest release, so drafts and prereleases are never
offered, and compares its version with the running one. The answer is that
this is the newest version, that a newer one exists, or that the check could
not be made, with the reason. A failed check never reports the copy as up to
date.

A package installed from a release then offers **Update to** the new version:

1. A question names the package for this system, such as Debian 13 amd64, and
   its size.
2. **Download and Install** downloads the package built for the same
   distribution and architecture to `~/.cache/amiga-file-forge/updates`, with
   progress and **Cancel**. It is checked against the `SHA256SUMS` file
   published with the release. A package that does not match is deleted and
   nothing is installed.
3. The system asks for the password, and `pkexec apt-get install` installs the
   package over the old one. Dismissing the prompt installs nothing and leaves
   the update offered. When the installation is refused, or `pkexec` is not
   available, the message gives the `sudo apt install` command to run instead.
4. **Restart Amiga File Forge** starts the new version.

Working images, preferences, profiles and the collection are kept. Closing the
About box does not stop a download, and reopening it shows the progress. While
a floppy disk is being read or written through Greaseweazle or a floppy
controller, the update is not installed and the application does not restart.

## Which installations can update themselves

Each release package now records the system it was built for in
`/opt/amiga-file-forge/package-target`, so the update takes the package made
for that system rather than guessing from the running one. The release
workflow checks that record, and that the published file name is the one the
update looks for, before it publishes a package.

The Docker service, a source checkout and a package built without a release
revision have no such record. They can check for a newer version, but the
button opens the release page instead of installing. Update those the way they
were installed. Only the desktop host can install, because only it runs as the
signed-in user where `pkexec` can ask for the password; the web host has no
route that installs anything. This is recorded as platform contract version 8.

Releases up to and including 1.4.1 have no `package-target` and no button, so
moving to 1.5.0 is done with APT as before. From 1.5.0, later releases can be
installed from the About box.

## Network use

Check for Application Updates joins the online library and the metadata lookup
as the only features that make outbound requests. It contacts GitHub only when
the button is pressed, and downloads a package only when the user chooses to
install it. The [security policy](../../SECURITY.md) and the
[installation guide](../INSTALLATION.md#check-for-application-updates) describe
it.

## Repair and format behaviour

No format restriction or repair behaviour has changed. An image that 1.4.1
opened is read and written the same way by 1.5.0.

## Linux packages

The release provides packages for Debian 13 and Ubuntu 24.04 on AMD64, ARM64
and ARMv7. Choose the file matching both the operating system and processor.
GitHub publishes the files with a dot where the package version has a tilde,
so the Debian 13 AMD64 package downloads as:

```bash
sudo apt install ./amiga-file-forge_1.5.0-1.deb13_amd64.deb
```

The packages include the native GTK launcher, desktop integration and the
bundled HxCFloppyEmulator runtime for HFE and SCP media, as they did in 1.4.1.
Installing 1.5.0 over an earlier release preserves native XDG workspace data
and Docker working volumes. Save important open images before upgrading.

See the [installation guide](../INSTALLATION.md) and
[Linux desktop guide](../LINUX-DESKTOP.md) for setup and troubleshooting.
