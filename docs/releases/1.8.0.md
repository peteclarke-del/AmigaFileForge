# Amiga File Forge 1.8.0

AmigaOS 3.5 and 3.9 are now installed by Amiga File Forge itself, with the
BoingBag update packs over the top.

## Installing from the CD

In 1.7.1, **Tools → Install AmigaOS 3.5 or 3.9…** started the emulator with the
disc attached and left the installation to be run by hand. Reaching a
Workbench with the disc mounted is not an installation.

The installation is now made directly and written into the open partition.
When it finishes, the drive holds the system and starts the machine. It is
made the way the PiStorm imager makes it: the layout of each release was read
out of the Installer script on its disc, and the trees are copied in order so
that the newest copy of each file is the one that lands.

| Release | Layers, in the order they are laid down |
| --- | --- |
| AmigaOS 3.9 | `Workbench3.5`, then `Workbench3.9` over it, then Locale, keymaps, printer drivers, updated commands, FastFileSystem, extra libraries and backdrops |
| AmigaOS 3.5 | Workbench 3.1 and Extras 3.1 from the disc, then the 3.5 `Workbench` over them, then the same additions |

The drive does not need a system on it. When it has one, files the release
carries replace the ones of the same name, and everything else on the drive is
left as it is. `S/User-Startup` is never replaced. The dialog lists what will
be installed before you commit to it, and an undo point is taken first.

Every language, keymap and printer driver on the disc is installed. The disc's
own installer asks which to leave out, and this does not.

## BoingBags

The same dialog takes the update packs. Choose the LHA archives you have, in
any order. One archive may hold several packs, and each pack found is listed
with a tick box.

| Pack | How it is applied |
| --- | --- |
| BoingBag 1 and 2 for AmigaOS 3.5 | Copied over the system |
| BoingBag 1 and 2 for AmigaOS 3.9 | Plain files are copied. The system fixes are applied by the pack's own Updater |
| BoingBags 3 and 4 for AmigaOS 3.9 | Copied over the system, with the build of each library chosen for the processor in the hardware profile |

BoingBags 1 and 2 for 3.9 keep their fixes in an archive in which every file
is encrypted. Amiga File Forge does not open it. It runs the pack's own
`Updater` in FS-UAE, with the release disc attached, and writes what the
Updater produced to the drive with the rest of the system. The emulator opens
a window of its own for a few minutes for each pack and closes it again.
Nothing needs doing in that window.

That needs FS-UAE and a Kickstart 3.1 ROM for the machine in the hardware
profile. Where either is missing, the plain files of those packs are still
installed and every fix that could not be applied is listed by name.

## Running the disc's own installer

Starting the emulator with the disc in its CD drive is still offered, as **Run
the disc's installer instead**, for choosing what the installer leaves out. It
is not needed to install the release.

## Repair and format behaviour

These changes affect how images are written:

- **Protection bits are kept when files are copied between volumes.** A
  numeric protection value was read as hexadecimal text. The value 32, which
  marks a command as pure, was written as 0x32, which denies execute, and the
  value 64, which marks a script, was written as 0x64. This affected **Install
  Workbench** from floppies and staging a title onto a drive. On the Workbench
  3.1 floppies only the four script files carry such a value, and they were
  written as pure and protected from writing, which does not stop the system
  starting. A disk whose commands are marked pure would have been left with
  commands that report "file is not executable". Correct any such file with
  **Properties**.
- **An archive whose files carry comments can be read.** The LHA reader took
  an Amiga file comment to be part of the file name. A comment holding a web
  address then looked like an absolute path, and the whole archive was
  refused. BoingBag 1 for AmigaOS 3.9 is such an archive.
- **The route that starts the emulator with a CD has moved.** It is now
  `POST /api/images/<id>/install/amigaos-cd/boot`. The former address installs
  the release and takes a form, not JSON.

## How this was checked

With the AmigaOS 3.9 disc and BoingBags 1, 2, 3 and 4, an empty 1 GB PFS3
partition was installed onto for an A1200 with a PiStorm32. Both Updater runs
applied every file their archives list, 210 and 157. The drive then started in
FS-UAE with Kickstart 3.1 to the AmigaOS 3.9 Workbench.

| Measure | Result |
| --- | --- |
| Files written | 3,497 |
| Time for each Updater run | about two and a half minutes |
| Time to write the drive | about two and a half minutes |
| Versions reported by the started machine | Workbench 45.5, icon.library 46.4, FastFileSystem 45.16 |

Not yet checked: a real AmigaOS 3.5 disc and its BoingBags, which are covered
only by discs built for the tests, the Updater run in the Docker edition, and
the installed drive on a real machine.

## Linux packages

The release provides packages for Debian 13 and Ubuntu 24.04 on AMD64, ARM64
and ARMv7. Choose the file matching both the operating system and processor.
The Debian 13 AMD64 package downloads as:

```bash
sudo apt install ./amiga-file-forge_1.8.0-1.deb13_amd64.deb
```

The packages include the native GTK launcher, desktop integration, the udev
rule for attached drives, the PFS3 handler, and the bundled HxCFloppyEmulator
runtime for HFE and SCP media. A package installed from 1.5.0 or later can also
update itself from **Help →
About Amiga File Forge → Check for Application Updates**. Installing 1.8.0
over an earlier release preserves native XDG workspace data and Docker working
volumes. Save important open images before upgrading.
