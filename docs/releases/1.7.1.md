# Amiga File Forge 1.7.1

A fix for installing AmigaOS 3.5 and 3.9 from CD. Anyone who uses **Tools →
Install AmigaOS 3.5 or 3.9…**, or who installs a title under emulation, should
upgrade: in 1.7.0 and earlier, booting with the CD could not work.

## Installing onto an empty drive

Choosing a release CD for a newly partitioned drive showed the disc as
recognised and the drive as not ready, which read as the disc having failed.
The drive was refused for being empty, on the grounds that AmigaOS 3.9 refuses
a drive with no earlier release on it.

That is not what the installer says. Its own words are "OS3.9 full
installation over OS3.0 or empty HD", for which it says to "boot from your
Emergency-Disk".

An empty drive is now installed onto. Both discs carry a complete system in a
drawer called `Emergency-Boot`. The machine is started from it, on a small
drive of its own attached beside the one being installed onto, because an
emulated A1200 does not boot from its CD drive. In the installer, choose the
full installation and give it the empty partition. Nothing from the emergency
system is put on your drive, and the small drive is discarded when the
emulator closes.

The dialog now reports the disc and the drive separately. A disc that is
recognised is said to be fine. A drive that nothing can start, which is an
empty drive and a disc with no emergency system, offers to install Workbench
3.1 from the dialog.

## Booting with the CD did not work

Four faults stood behind the message, each enough on its own.

| Fault | Effect |
| --- | --- |
| The emulator was given a FAT32 card image with the drive wrapped inside it | It could not boot, was limited to 4 GB, and was deleted afterwards |
| FS-UAE installed as a snap cannot read the workbench's hidden working folder | The machine started with no drive |
| The undo point was named after a reason too long for the checkpoint store | Every request was refused |
| The undo point was discarded as soon as the request returned | There was no way back after an install |

The emulator is now given the drive in the pane itself, so what the installer
writes is on the drive when the emulator closes. An undo point is taken before
the machine starts and kept, and **Edit → Undo last change** afterwards puts
the drive back as it was.

Where FS-UAE is a snap, the drive and the disc are given to it under a second
name in `~/snap/fsuae/common/amiga-file-forge`, which it can read. That is a
hard link and not a copy, so a drive of a hundred gigabytes is handed over at
once. Where a hard link cannot be made, because the two folders are on
different disks, the drive is copied without its empty space and copied back
when the emulator closes.

The same applies to installing a title under emulation, which boots a drive
with the title's floppies inserted.

## Repair and format behaviour

These changes affect how images are written:

- **No CD mountlist is written to the drive.** Booting with a CD used to copy a
  `CD0` mountlist into `Devs/DOSDrivers` that named the emulator's own CD
  device. The emulator mounts the disc as `CD0:` itself, so the mountlist was
  not needed, and it would have been wrong on the real machine the drive is
  for. A drive that 1.7.0 or earlier booted with a CD may carry one. Delete
  `Devs/DOSDrivers/CD0` if it names `uaescsi.device`.
- **A drive cannot be changed while it is in the emulator.** Changes and
  rollbacks are refused until the emulator is closed, because two programs
  writing to one drive corrupt it.
- **A drive run to look at it is attached read-only.** **Tools → Run hard
  drive…** no longer writes to the image. Software that saves to the drive
  will report that it is write-protected.

## How this was checked

In FS-UAE with Kickstart 3.1 and the AmigaOS 3.9 disc, an empty PFS3 drive
started from the emergency system to Workbench 45.1, with the disc as `CD0:`
and the empty partitions mounted and writable. A file the machine wrote was in
the image afterwards. A drive with Workbench 3.1 saw the disc with no CD driver
switched on.

Not yet checked: the installer run to completion, an AmigaOS 3.5 disc, and the
Docker edition, whose FS-UAE is given the image where it is.

## Linux packages

The release provides packages for Debian 13 and Ubuntu 24.04 on AMD64, ARM64
and ARMv7. Choose the file matching both the operating system and processor.
The Debian 13 AMD64 package downloads as:

```bash
sudo apt install ./amiga-file-forge_1.7.1-1.deb13_amd64.deb
```

The packages include the native GTK launcher, desktop integration, the udev
rule for attached drives, the PFS3 handler, and the bundled HxCFloppyEmulator
runtime for HFE and SCP media. A package installed from 1.5.0 or later can also
update itself from **Help →
About Amiga File Forge → Check for Application Updates**. Installing 1.7.1
over an earlier release preserves native XDG workspace data and Docker working
volumes. Save important open images before upgrading.
