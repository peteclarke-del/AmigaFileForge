# Amiga File Forge 1.2.0

Amiga File Forge 1.2.0 can install a floppy onto a hard drive rather than only
copy it there. Copying a game disk into an HDF gives you the files, not
something that runs: the title still expects `DF0:`, and the drive still has no
idea it is there. Three methods now close that gap, and which three exist was
decided by what can be done honestly rather than by what reads well in a list.

## Installing a disc

The import dialog offers **Install it onto this drive** alongside copying the
contents and storing the image, wherever the destination pane is a mounted
AmigaDOS volume on a hard drive. A floppy pane offers nothing, because a floppy
has nowhere to install to, and a drive showing its partition table offers
nothing either, because a partition table is not a volume.

- **Stage it for installing later** is the default, and it is the only method
  that cannot half succeed. Each disc is extracted into a drawer named for the
  title, and later discs of a set merge into the same tree. Nothing is
  emulated, downloaded or guessed at.
- **Install with WHDLoad** covers games and demos. The drive is checked for
  `C:WHDLoad`, its version is read from the program's own `$VER:` string, and
  the current release is installed if there is none.
- **Run the disc's own installer** boots the drive under emulation with the
  disc already in `DF0:`, for software that asks questions no tool can answer
  on somebody else's behalf.

Every method stages first, so an install that fails halfway has still preserved
the disc's contents somewhere they can be finished by hand.

**Tools -> Staged installations** lists what is waiting, installs a title into
an open volume, and discards one. That is how a multi-disc set is finished
after its last disc is staged, either here or by copying the staging drawer to
a real Amiga.

## What staging preserves, and what it refuses to lose

Where two discs of one title carry the same path with different contents, the
first is kept and the second is filed under `alternates/`. A set is never
silently reduced to whichever disc was staged last, and the conflict is
reported rather than resolved by guesswork, because which file an installer
wants is not knowable from outside it.

Staging a disc under a label that is already present is treated as a
correction, not as a second disc. Its files replace what the earlier attempt
left behind, and any conflict recorded against that disc is dropped. Filing the
correction away as an alternative would leave the broken file in place, which
is the opposite of what was asked for.

Protection bits and comments travel in the same `.inf` sidecar this application
already writes on export and reads on import, so a staged tree brought back in
keeps them. A loader that has lost its `e` bit will not start and does not look
broken, which is why this is handled rather than left to chance.

Staged titles are kept under the working directory. Set
`AMIGA_INSTALL_STAGING_DIR` to write them straight to a share or a card the
Amiga can reach.

## WHDLoad, and the half of it that cannot be fetched

The WHDLoad program is installed from its author's site at `whdload.de`, with
Aminet as a fallback. The `C:` tools and the `S:` startup and cleanup scripts
are copied directly rather than by running the archive's own `Install` script
under emulation: the destinations are fixed and known, so booting a machine to
rediscover them would cost a minute per image and add a way to fail that
copying does not have. An existing `S:WHDLoad.prefs` is never overwritten, so
preferences tuned for a particular machine survive a reinstall, and a drive
that already has WHDLoad is left alone unless reinstalling is asked for.

The per-title slave cannot be downloaded from anywhere. The author's site
refuses its game index to anything that is not a browser session, and Aminet
carries WHDLoad itself but no slaves. There is therefore no button for it,
because a button that always failed would be worse than none. A slave is
accepted bare or still inside the small archive it was published in, and an
install without one is reported as incomplete rather than presented as
finished: the drawer and its files are ready for the slave whenever it arrives.

## LHA archives

Amiga File Forge now reads LHA. It could not before, and there is no `lha` or
`lhasa` in the container; adding one would have made the feature depend on a
package present in the container and absent from the Debian and Snap builds,
which is the kind of split that only shows up on a user's machine. DMS is
already decoded in this tree for the same reason.

Header levels 0, 1 and 2 are parsed, and the `-lh0-`, `-lh4-`, `-lh5-`,
`-lh6-` and `-lh7-` methods are decompressed, which covers what the Amiga world
produced. Every member is checked against the CRC the archive stores for it, so
a damaged download is reported rather than written into a disk image. A method
this build cannot expand still lists correctly and names itself when read,
because "this archive uses `-lh1-`" is a fact somebody can act on.

The reader was run over all 562 members of the current `WHDLoad_usr.lha`, every
one of which passes its stored checksum, and cross-checked against `unar`. It
matches on every member `unar` decoded and is correct on one that `unar` wrote
out as zero bytes.

## Other changes

- Find FS-UAE where it is actually installed, including the Snap and other
  packaging layouts, instead of assuming one path. A machine with no Kickstart
  ROM for the selected model now says so rather than silently using the first
  ROM in the directory, which gave every machine the CD32 extended ROM.
- Publish the Compose service on ports that are not already taken by a sibling
  application, configurable through `AMIGA_FILE_FORGE_PORT` and
  `AMIGA_FILE_FORGE_VNC_PORT`.
- Record release checksums under the names the release actually publishes.
  GitHub rewrites `~` in a package filename to `.`, so the published
  `SHA256SUMS` named files that did not exist.
- Allow local Kickstart ROMs in `firmware/` and ignore them, so an operator can
  supply the ROMs the emulator needs without any risk of committing material
  that is not redistributable.
- The firmware test now checks what the repository tracks rather than what is
  in the directory. Its point is that no ROM is shipped, and `firmware/` is
  exactly where an operator is told to put their own, so reading the directory
  failed on any machine that had followed the instructions.

## Repair and format behaviour

This release adds ways to write into a hard-drive image; it does not change how
any existing write is performed. Installing a staged title uses the same host
import path, the same filename policy and the same loader repair as a plain
copy, so a title installed this way is written exactly as one copied in and
then repaired by hand would be. No format restriction has changed, and no image
written by 1.1.1 is read differently by 1.2.0.

Installing a staged title, installing WHDLoad and adding a slave each take an
undo checkpoint before they run. Staging changes no image and takes none.

## Performance record

The full benchmark profile for this release is attached to the GitHub Release
as `benchmark-full-1.2.0.json`. It records minimum, median and maximum
durations over five runs for partition listing, catalogue listing, tree
browsing, bulk import into an FFS hard disk, Hardfile listing and
checkpointing, and the complete Hardfile save archive.

No like-for-like comparison with the previous release is offered, because no
full-profile record was retained for it; the only earlier record is a quick
profile taken in CI over a fifth of the data. The paths these figures cover are
unchanged by this release, which adds new routes into the existing host-import
and volume-write code rather than altering it.

## Linux packages

The release provides packages for Debian 13 and Ubuntu 24.04 on AMD64, ARM64
and ARMv7. Choose the file matching both the operating system and processor.
For example:

```bash
sudo apt install ./amiga-file-forge_1.2.0-1~deb13_amd64.deb
```

The packages include the native GTK launcher, desktop integration and the
bundled HxCFloppyEmulator runtime for HFE and SCP media.

Installing 1.2.0 over 1.1.1 preserves native XDG workspace data and Docker
working volumes. Save important open images before upgrading.

See the [installation guide](../INSTALLATION.md) and
[Linux desktop guide](../LINUX-DESKTOP.md) for setup and troubleshooting.
