# Amiga File Forge 1.3.1

A fix for the Linux desktop application. Anyone running the native package who
tried to install Workbench from a collection folder should upgrade; the web and
Docker editions are unaffected by the main fault.

## Choosing a folder in the desktop application

Pointing the Workbench install at a folder of disk images recognised a single
disc, whatever the folder held.

The install was not at fault. The same collection surveys correctly in a
browser, and the recognition reads the zipped-per-disk form a TOSEC collection
uses and takes the volume name out of each image as intended. What failed was
choosing the folder.

The page asks for a directory the way a browser offers one. WebKitGTK, which
renders the page inside the desktop application, has no concept of a directory
anywhere in its file chooser: the whole selection surface is whether multiple
files are allowed, the accepted types, and the files chosen. A directory
request is therefore ignored and an ordinary file chooser opens, which a
folder cannot be picked in, so whichever single file was selected became the
entire set.

The desktop host answers that request itself now. The page says a folder is
wanted, the host opens a real folder chooser, and every ordinary file below the
chosen folder is handed back, which is what a browser would have supplied.
Nothing about the page or the install changed, so the two editions behave the
same way again.

Symbolic links are skipped, so a collection folder that links to itself, or to
the root of a drive, is not followed until something gives way. The selection
stops at two thousand files, which is far above a complete AmigaOS release and
above a TOSEC Workbench folder, and well below a whole collection drive.

## A disc that boots an operating system of its own

Opening an Amiga UNIX install disc reported that it was unformatted, truncated
or damaged. It is none of those. Those discs carry an Amiga boot block that
chain-loads the UNIX bootstrap and no AmigaDOS filing system at all, so there
is no root block to find, and calling the disc damaged sends somebody looking
for a fault in a dump that is perfectly good.

The message now says what such a disc is, and that its bytes can still be read
in the hex editor. This applies to any disc built that way, not only Amiga
UNIX.

## Repair and format behaviour

Nothing about how an image is read or written has changed. No format
restriction has changed, and no image written by 1.3.0 is read differently by
1.3.1.

## Linux packages

The release provides packages for Debian 13 and Ubuntu 24.04 on AMD64, ARM64
and ARMv7. Choose the file matching both the operating system and processor.
For example:

```bash
sudo apt install ./amiga-file-forge_1.3.1-1~deb13_amd64.deb
```

The packages include the native GTK launcher, desktop integration and the
bundled HxCFloppyEmulator runtime for HFE and SCP media, as they did in 1.3.0.

The folder fix is in the desktop host rather than in the page, so it arrives
with the package rather than with a reload. Installing 1.3.1 over 1.3.0
preserves native XDG workspace data and Docker working volumes. Save important
open images before upgrading.

See the [installation guide](../INSTALLATION.md) and
[Linux desktop guide](../LINUX-DESKTOP.md) for setup and troubleshooting.
