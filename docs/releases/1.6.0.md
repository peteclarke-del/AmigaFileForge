# Amiga File Forge 1.6.0

Real Amiga drives. A hard drive or memory card taken from an Amiga can be
attached through a USB adapter and opened where it is, and the filing systems
such drives use are now read and written: the Smart File System, PFS3 and
every variant of FFS. This release also fixes copying files between panes,
which did not work for floppies in 1.5.0.

## Drives attached through USB

In the Linux desktop application, **Open attached drive** on an empty pane, or
**File → Open attached drive…**, lists the disks behind a USB controller, each
with what it holds. The machine's own disks are never listed.

A drive is not copied, because it can be far larger than the working storage
and the point is to change the drive itself. It opens read-only. **File →
Allow writes to drive…** lets changes through, and they then go straight to
the drive with no undo. A drive that Linux has mounted is refused, because two
systems writing to one drive corrupt it.

Linux gives whole drives to the administrator only. The package carries a
udev rule that lets the desktop user open USB disks, but does not install it,
because it covers every USB disk and not only Amiga ones. The
[Linux desktop guide](../LINUX-DESKTOP.md) gives the commands.

Two new commands work on a drive without passing it through the working
storage:

- **File → Export drive to image file…** copies the drive to a file chosen in
  a Save dialog: the drive as its partition table describes it, every byte of
  the device, or one partition as a hardfile with its `.geo`. Empty space is
  not written, and a stopped copy leaves no file behind. The export button in
  the pane header does the same.
- **File → Copy drive to another drive…** writes a copy over another attached
  drive, to set up a second machine or to move to a new card. The drive to be
  erased must be large enough, unmounted and writable, and is named again
  before anything is written. Every byte is written, then read back from the
  drive and compared with the original.

## Filing systems

| Filing system | 1.5.0 | 1.6.0 |
| --- | --- | --- |
| Smart File System, `SFS\0` | named only | read and write |
| Professional File System 3, `PFS\1` to `PFS\3` and `PDS\3` | named only | read and write |
| FFS Directory Cache, `DOS\4` and `DOS\5` | written, but the cache was left stale | read and write |
| FFS long filenames, `DOS\6` and `DOS\7` | named only | read and write |

SFS and PFS3 work alone in a file, as a partitionless emulator hardfile, or
inside a partition. Each partition now reports its own filing system and name
length, so names of up to 100 characters on SFS, up to 106 on PFS3 and up to
107 on the long-filename variants are accepted wherever a name is typed. A
partition for another system, such as CrossDOS, is listed with its DOS type
and cannot be opened, as is `SFS\2`.

SFS and PFS3 were checked against the real filing systems on an emulated
A1200. SFScheck and PFS3's DiskValid accepted volumes built and changed here,
and every change the real filing system then made read back intact. The
Kickstart 3.1 FastFileSystem listed Directory Cache volumes written here
without a difference. Long-filename volumes follow the layout amitools
documents; no AmigaOS 3.2 FastFileSystem has yet checked one written here.

## Copying between panes

- Dragging files between two floppies or single volumes failed in 1.5.0 and
  earlier. It works again.
- Dragging into a partition of a hard drive failed. It works, including
  between two partitions of the same drive.
- A whole partition can be dragged, from the partition table or a partition
  pane, into a drawer or onto another drive's partition.
- A copy that would replace an existing file, use a name the destination
  cannot hold, or overrun its free space is refused before anything is
  written, rather than stopping part way.
- A copy shows each file as it is written and can be stopped from **Jobs**.
- In the Linux desktop, dragging several files copied only the first, and the
  drag image stayed on screen until the application closed. Both are fixed.

Copying many files onto an FFS volume is also much faster. Copying the 333
files of a Workbench `C` drawer took 37 seconds and now takes under two.

## Repair and format behaviour

These changes affect how images are written:

- Every change to a Directory Cache volume now updates the directory caches.
  A volume written by 1.5.0 or earlier may carry stale caches, which a real
  machine shows as missing or out-of-date entries. **Check filesystem**
  reports them.
- The long-filename variants were read-only and are now written.
- The FFS repairs made when a hardfile is saved, which rewrite block
  checksums and the root block's datestamp, are no longer applied to SFS or
  PFS3 volumes, whose blocks are laid out differently.

An OFS or FFS image that 1.5.0 opened is read the same way by 1.6.0.

## Linux packages

The release provides packages for Debian 13 and Ubuntu 24.04 on AMD64, ARM64
and ARMv7. Choose the file matching both the operating system and processor.
The Debian 13 AMD64 package downloads as:

```bash
sudo apt install ./amiga-file-forge_1.6.0-1.deb13_amd64.deb
```

The packages include the native GTK launcher, desktop integration, the udev
rule for attached drives, and the bundled HxCFloppyEmulator runtime for HFE
and SCP media. A package installed from 1.5.0 can also update itself from **Help → About
Amiga File Forge → Check for Application Updates**. Installing 1.6.0 over an
earlier release preserves native XDG workspace data and Docker working
volumes. Save important open images before upgrading.

See the [installation guide](../INSTALLATION.md) and
[Linux desktop guide](../LINUX-DESKTOP.md) for setup and troubleshooting.
